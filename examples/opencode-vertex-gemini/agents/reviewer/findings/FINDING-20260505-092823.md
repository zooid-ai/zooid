# Implement trailing-edge timer that fires the last-seen args

**File:** src/throttle.ts
**Severity:** high
**Type:** api-contract

## Contract (as I understand it)

The throttle should behave as a leading+trailing edge throttle: the first call in a quiet period fires immediately (leading edge), and any calls during the cooldown window are coalesced so that only the **last** arguments fire exactly once on the trailing edge at `lastFire + ms`. After that trailing call, a new quiet period begins.

## What the implementation does

```typescript
19:   let lastFire = 0
20:
21:   return function throttled(...args: unknown[]): void {
22:     const now = Date.now()
23:     if (now - lastFire >= ms) {
24:       lastFire = now
25:       fn(...args)
26:     }
27:   } as T
```

The implementation only tracks `lastFire`. When a call arrives within the cooldown window (`now - lastFire < ms`), it is silently discarded. There is no stored `lastArgs`, no `setTimeout` for a trailing edge, and no mechanism to ever fire after the cooldown elapses. The function is a pure leading-edge throttle with drop semantics — not a leading+trailing throttle.

## Why this is wrong

Consider: `throttle(fn, 100)` is called with:

- t=0: `t('a')` → fires immediately, `lastFire=0`, `fn('a')` called
- t=20: `t('b')` → dropped (20 - 0 < 100)
- t=50: `t('c')` → dropped (50 - 0 < 100)
- t=100: (trailing edge should fire) → nothing happens

The contract requires `fn('c')` to be called at t=100 with the last-seen args. The implementation fires `fn` exactly once with `'a'` and never again. Any caller relying on trailing-edge delivery (e.g., the "search-as-you-type" use case mentioned in the header comments on line 4) will silently lose user input.

## Test gap

The test at `src/throttle.test.ts:16-25` ("drops calls inside the cooldown window") asserts:

```typescript
t('a')           // leading call
vi.advanceTimersByTime(20)
t('b')
vi.advanceTimersByTime(20)
t('c')
expect(fn).toHaveBeenCalledTimes(1)
```

This test **validates the buggy behavior** — it expects exactly 1 call, which matches the drop-semantic implementation. It never advances timers to `t=100` to check for a trailing invocation, and it never asserts that `fn` was called with `'c'`. No test in the suite verifies trailing-edge delivery at all.

## Suggested fix

Add a `let timerId: ReturnType<typeof setTimeout> | undefined` and `let lastArgs: unknown[] | undefined` variable alongside `lastFire`. Inside the cooldown branch (the `else` of line 23), store `lastArgs = args` and schedule a `setTimeout` to fire `fn(...lastArgs!)` at `ms - (now - lastFire)` ms from now. Clear and reschedule this timer on every new call during cooldown so that only the final trailing call fires once. Reset both `timerId` and `lastArgs` after the trailing edge executes.
